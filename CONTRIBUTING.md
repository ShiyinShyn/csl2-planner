# 反馈与贡献指南 / Feedback and Contribution Guide

[中文](#中文) · [English](#english)

## 中文

### 当前政策

CSL2 Planner 由作者独立维护，处于早期开发阶段，暂无可用发布版本。

- **欢迎反馈**：通过 GitHub Issues 提交需求、问题报告、文档纠错或功能建议，也欢迎在相关 Issue 下评论讨论。
- **暂不接受外部 PR**：为保持开发方向与架构的一致性，现阶段不接受未经邀请的代码、文档或其他 Pull Requests。
- **先讨论，再贡献**：若希望提供修改，请先创建或参与相关 Issue，等待维护者明确邀请后再提交 PR；讨论或正面回应本身不等于邀请。
- **不承诺处理时限**：反馈不保证被采纳、回复或实现。未经邀请的 PR 可能直接关闭，不承诺审查或合并。

### 如何提供有效反馈

提交前，请先阅读 README 并检索已有 Issues，避免重复报告。

问题报告尽量包含：

1. 问题概述，以及预期行为和实际结果。
2. 可重复的步骤；涉及环境或脚本时，提供操作系统、Python/Conda 版本和相关包版本。
3. 必要的错误摘要，以及尽可能小的合成数据或代码示例。

功能建议请说明使用场景、要解决的问题和期望结果。README 中尚未实现的规划功能不是可用版本；请区分环境/文档问题与未来功能需求。

### 数据与隐私

不要在公开 Issues、评论、日志或附件中发布密码、Token、私钥、个人信息、私人目录路径或无权分发的数据。
原始游戏存档、完整 Carto 导出和指南图片不是必需的反馈附件；优先使用脱敏摘要和轻量合成数据。
涉及敏感安全问题时，不要公开可利用细节或真实凭据。

资料范围见 [DATA_SOURCES.md](DATA_SOURCES.md)。Fork 及自行修改是欢迎的，但不表示维护者承诺审查或合并；使用和分发请遵守 [LICENSE](LICENSE)。

## English

### Current policy

CSL2 Planner is independently maintained by its author, is in early development, and has no usable release yet.

- **Feedback is welcome**: Use GitHub Issues for user needs, bug reports, documentation corrections, feature suggestions, and discussion. Comments on relevant issues are also welcome.
- **External PRs are not being accepted at this stage**: To keep the project's direction and architecture consistent, unsolicited code, documentation, and other pull requests are not accepted.
- **Discuss before contributing**: Create or join a relevant issue and wait for an explicit invitation from the maintainer before submitting a PR. Discussion or a positive response alone is not an invitation.
- **No guaranteed timeline**: Feedback does not guarantee acceptance, a response, or implementation. Unsolicited PRs may be closed without review or a commitment to merge.

### Providing useful feedback

Read the README and search existing issues before posting to avoid duplicate reports.

For a problem report, please include where practical:

1. A short description, expected behavior, and actual results.
2. Reproduction steps; for environment or script problems, include your operating system, Python/Conda versions, and relevant package versions.
3. Essential error messages and the smallest possible synthetic data or code example.

For a feature suggestion, explain the use case, the problem, and the desired outcome. Planned features in the README are not available releases; distinguish environment/documentation problems from future feature requests.

### Data and privacy

Do not publish passwords, tokens, private keys, personal information, private directory paths, or data you do not have permission to redistribute in public issues, comments, logs, or attachments.
Raw game saves, complete Carto exports, and guide images are not required feedback attachments; prefer sanitized summaries and small synthetic examples.
For sensitive security concerns, do not publicly disclose exploitable details or real credentials.

See [DATA_SOURCES.md](DATA_SOURCES.md) for the publication scope. Forks and independent modifications are welcome, but do not imply a commitment to review or merge them. Follow [LICENSE](LICENSE) when using or distributing the project.
