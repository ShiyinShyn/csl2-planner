## 1. 查证结论与证据边界

本轮所查本地材料能够确定权限、白名单、机场去重、来源追踪要求和若干定性关系，但没有找到足以直接冻结的居民/就业规模派生系数、分目的出行率、小汽车乘员率或公路货运转车次系数。这个结论仅针对已查材料，不表示外部资料不存在，也不表示产品必须依赖游戏遥测才能继续研发。

本地指南中的游戏机制说明、现实工程参考和作者建议必须分别登记。来源出现数值，不等于该数值可作为本项目默认；资料已读，也不等于机制已在指定游戏版本验证。

外部查证本轮未取得可引用正文：两次公开检索没有返回可用标题、URL 或正文证据；一次官方域名候选页面获取被工具拒绝，提示无法验证域名安全，可能与网络限制有关。未换工具绕过访问限制、未下载或安装。外部条目全部保持未核实，不能据此证明数值存在或不存在。

### 3.1 维度示例与变量说明

本节只说明候选口径的一致性，不选定生产模型或系数。

| 符号 | 含义 | 单位/约束 |
|---|---|---|
| $A$ | 与密度来源采用同一分母口径的面积 | m²；不能以地块总面积替代楼面面积 |
| $d$ | 有明确面积口径的规模密度 | 人/m²；值尚未查明 |
| $N$ | 由该口径得到的规模 | 人；库存数量，不是人次 |
| $r_{p,\tau}$ | 对目的 $p$ 和时段 $\tau$ 的出行率 | 人次/(人·时段)；时段长度及现实/模拟时间须明确 |
| $T_{p,\tau}$ | 对应目的和时段的出行量 | 人次/时段 |
| $T^{car}_{p,\tau}$ | 已归属小汽车方式的出行量 | 人次/时段；不能代入全部客运量 |
| $o_{p,\tau}$ | 同口径小汽车平均乘员率 | 人次/车次；转换时必须大于零 |
| $V_{p,\tau}$ | 对应小汽车交通量 | 车次/时段 |
| $F_{k,\tau}$ | 同货种/车型口径的公路货物量 | 例如 kg/时段；游戏资源单位不能未经依据等同 kg |
| $q_{k,\tau}$ | 同口径有效平均载荷 | 例如 kg/车次；必须大于零，不能直接用标称最大载荷 |
| $V^f_{k,\tau}$ | 对应载货车交通量 | 车次/时段；空驶/回程需另有来源，不能自动乘二 |

仅在各自前提和统计范围匹配时，维度可写为 $N=A d$、$T_{p,\tau}=N r_{p,\tau}$、$V_{p,\tau}=T^{car}_{p,\tau}/o_{p,\tau}$、$V^f_{k,\tau}=F_{k,\tau}/q_{k,\tau}$。这些表达式不保证目的、混合构成、机场批次或配送任务已经去重，不代替 P 核心校验。

不可把现实“一天”、模拟“一天”和墙钟运行时间互换。人口/就业库存、单时段总量和单位时间流率分别登记；任何换算都要保留时间基准、时段长度、适用版本和出处。

## 4. DraftCatalog 字段草案

### 4.1 数据组织

建议分目录头、来源记录、参数记录三层；一个参数可引用多个来源，一个来源可支撑多个参数。以下字段由 Q 草案描述，正式消费 schema 与 P 侧共同核对后再冻结。

| 层级 | 字段草案 | 必需语义 |
|---|---|---|
| 目录头 | draft_schema_version、catalog_version、status、consumer_baseline_refs | 区分结构/内容版本、draft 状态、需求与消费者基线；不只靠日期识别版本 |
| 来源记录 | source_id、source_kind、locator、source_version、game_version_scope、evidence_status、verification_notes | 可定位章节/符号/URL；版本未知显式记录；本地已读、外部未读与游戏实测分别表达 |
| 参数身份 | parameter_id、name、parameter_domain、definition、component | 情景需求、服务或几何分开；component 描述住宅/商业等业务构成，不新增核心用地枚举 |
| 适用范围 | land_use_types、business_subtypes、mode_scope、purpose_scope、period_basis | 引用现有用地类型；子类型不能替代 P 映射；不允许未知范围默认全部适用 |
| 数量语义 | unit、quantity_basis、time_basis、conversion_notes | 原始/规范单位、库存/总量/流率、统计对象、模拟/现实时间与允许换算依据 |
| 值与出处 | value、range、value_status、source_refs、assumptions | 未知 value 为空并有缺口；range 仅在有依据时填写，不能虚构敏感性区间 |
| 约束与使用 | validity_constraints、usage_limit、rule_refs | 例如除数须大于零；权限引用 D5，不由 Q editable 字段授权；几何约束不得借情景覆盖放松 |
| 缺口 | gap、next_evidence、consumer_task | 描述缺证、下一核查动作、供给任务；模型选择交给 P 或 G0 签认 |

### 4.2 状态与使用规则

- `evidence_status` 建议至少区分 `LOCAL_READ`、`LOCATED_ONLY`、`EXTERNAL_UNVERIFIED`、`VERSION_BOUND_VERIFIED`；前两者不等于机制验证，最后一项需绑定明确版本和证据。
- `value_status` 建议区分 `UNKNOWN`、`EVIDENCED_CANDIDATE`、`THEORETICAL_ASSUMPTION`、`REFERENCE_ONLY`、`SYNTHETIC_ONLY`、`RULE_ONLY`。这些是草案，不修改已有错误枚举或契约。
- `EVIDENCED_CANDIDATE` 只表示存在依据，不等于默认已批准；理论假设须有模型版本、适用条件、限制和后续批准记录。
- 生产默认的批准与来源验证分开记录；Q 文档不产生默认批准。没有游戏精确系数时，可按实施计划提交可解释理论假设及敏感性方案，不能擅自选值，也不把遥测设为全部研发的硬前置。
- UNKNOWN 不可被数值 0、空目录、前端只读或缺少图层悄悄消解。合成值保留在测试用途，不能提升为候选默认。
- D5 权限由实际用地类型与 P 核心实施：住宅/含住宅商住混合可以按合法字段继承和覆盖；非住宅固定系统版本。几何、街区尺度和拆迁权限不被情景参数锁定误伤。
- 指南有步行和非公路货运描述时，只登记来源背景与拒绝范围；不改变首版白名单。机场同批客流只能由明确网关计入，不能另建 TAZ 或再算宿主一般产生量。

## 5. 下个检查点及交接条件

### 5.1 优先查证清单

1. 核对可访问的官方机制/版本资料中居民、家庭、住宅单元、就业容量及实际就业的定义；找不到面积系数时保留缺口，不按建筑占地外推楼面/人口。
2. 核对目的、模拟时段、迁入与普通出行的关系，尤其本地指南办公通勤陈述的适用版本；保持定性与定量证据分开。
3. 核对小汽车统计是否按单人任务或同行乘员、是否包含驾驶者及车辆用途；只有座位数不能推平均乘员率。
4. 核对公路货运原始资源单位、载荷与车次、配送合并及空驶；将可证实口径与待定模型项交 P，不能混入非公路货运。
5. 收集 P0-03/P0-05 消费反馈后确定 Q 自有机器目录与有界校验入口；来源/参数空缺可被目录明确表达，不能先改 P 的 ScenarioValues 来迎合草案。
