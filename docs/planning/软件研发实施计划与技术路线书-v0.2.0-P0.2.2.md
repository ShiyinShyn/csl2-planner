## 1.【系统需求与数据流分析】

### 1.1 产品目标、系统边界与需求分层

产品为个人开发者与 AI 辅助研发的独立 Windows 桌面工具，本地单机、单用户、离线优先。使用原生 GUI 提供“候选推荐 → 手动调整/锁定 → 增量重算”的闭环；GIS 文件和报告是附加输出，不能取代软件界面。系统不是 QGIS 插件或游戏 Mod，不读取动态遥测、不修改存档、不自动施工。

五个业务原子单元均保留完整输入、候选、校核、编辑、重算和输出链路。内部算法分阶段验证，不把政策原型或阶段性模块子集宣称为完整首版。

| 编号 | 业务能力与边界 | 核心成果 | 当前验证状态 |
|---|---|---|---|
| FR-LU | 陆水、开发/保护建议、地形分区、宏观功能自动分配与用户修改 | 唯一 PlanningZone（用地分区=TAZ）、功能/需求参数与保护约束 | P0-01 单实体/参数契约通过；P0-02 水域/未知掩膜与格网对齐已验证；陆地语义待确认、完整功能生成未实现 |
| FR-RN | 理论四阶段法、道路外部连接、四级路网、逐分区独立街区尺度 | 分时段/分目的 OD、需求、分级路网与流量 | 逐区数据和禁拆政策契约通过；完整需求与网络生成未实现 |
| FR-ID | 出入口、内部车行组织、配建与公共停车 | 入口、车行/转向、停车容量与运行评价 | 共享禁拆政策可复用；微观组织未实现，不生成慢行网络 |

| FR-HW | 公路入城接点、规划级 TIA、立交/匝道平面纵断面与净空包络 | 接点比较、建设/无建设/改善场景、几何与交通报告 | 禁拆形态裁决通过；TIA 与立体线形未实现 |
| FR-GUIDE | GUI 内独立离线指南查看，目录、搜索、正文和图片 | 可移植本地查看器，不增加编辑器 | GUI、资源路径和发行权利待 P0-04 |

**刚性范围**：

1. 用地分区与 TAZ 在拓扑、属性、主键和生命周期上是同一实体；街区和原始游戏 Zoning 单元不是另一套规范 TAZ。
2. 保留宏观功能规划，但严禁生成、移动、旋转或摆放普通住宅、商场、工厂、学校、医院等非交通建筑；已有建筑只作需求背景和现状障碍。
3. 客运仅纳入道路小汽车、公交、地铁、客运铁路、客运海运。排除有轨电车、出租车、步行/骑行网络和接驳、内部航空网络；货运仅公路运输，不加入非公路货运或物流链。
4. 机场仅宏观外部产生/吸引点与地面多式联运枢纽，不设计跑道、航空航线或航站楼内部客流网络。
5. 住宅和含住宅的商住混合情景参数及用户默认可编辑；其它非住宅使用固定版本系统默认。分区功能、街区几何和拆迁开关不属于该情景参数锁定范围。
6. 用户硬保护、不可拆迁、人工锁定与游戏物理条件不得通过软惩罚或自动松绑绕过。不可拆迁现状冲突只能尝试地下，高架从屋顶上方跨越也禁止。
7. 预测完全基于理论模型，未做游戏观测校准不是首版阻塞条件；不保证消除拥堵，也不宣称复现游戏 AI。
8. 规划级平面、纵断面、净空与包络校核不等于现实工程安全认证。未知现状/地下资料须明示，不自动当作无障碍。

非功能要求包括原始数据只读、可追溯工程、可取消作业、编辑撤销、锁定保护、失败恢复、版本隔离和离线运行。当前样例是未来 G0 性能基准，不采用历史团队工期或未经实测的耗时/内存承诺。

### 1.2 真实样例审计与适配结论

本地样例目录：`GIS-files-example/`。原始数据不随公开仓库分发；下述为已有本地样例的审计摘要。公开自检使用合成数据，数据与资料范围见 [DATA_SOURCES.md](../../DATA_SOURCES.md)。

归档样例审计使用 TIFF 元数据与像素读取、SHP/DBF 文件头和属性读取进行只读检查；这是 v0.1.0 留存证据，P0-01 未重跑真实样例。结果已保存至 `docs/planning/carto-sample-data-audit.json`。**未进行全量几何有效性、路网连通性或游戏内对照验证。**

| 实际文件（统一前缀为 ZUTTOMAYO CITY） | 实测结构/规模 | 接口用途及风险 |
|---|---|---|
| `Elevation.tif` | 4096 × 4096，Float32，3.5 m/像素；有效高程约 22.9535–618.7126 m | 必选 DEM；高程基准须保留为游戏基准，不当成真实海拔 |
| `Depth.tif` | 2048 × 2048，Float32，7 m/像素；有效水深约 0.00004953–172.6516 m | 水域必选输入的一种合规载体；先排除 NoData，再提取水域 |
| `Area_Boundary.shp` | 536 面：529 个 MapTile、7 个 District | 地图范围、地块解锁状态与行政区；行政区不是天然 TAZ |
| `Building_Boundary.shp` | 3,127 面；含 Resident、Employee、Category、Zoning | 现状居民/就业与设施约束；不能直接等价为未来需求 |
| `Network_Centerline.shp` | 3,967 线；Road 2,204，Track 746，Pathway 684，Waterway 266，Taxiway 63，Runway 4 | 多模式网络；须分类后建图，不能将所有线当成道路 |
| `Network_Boundary.shp` | 3,963 面 | 路权/占地与现状障碍；与中心线记录数不同，不能按行号一对一关联 |
| `POI_Location.shp` | 845 点；含 Parking、StopBus、StopSubway、TrafficLight 等 Category | 现状设施与站点补充；点位不代表设施规模、容量或完整信号配时 |
| `Route_Centerline.shp` | 21 线：Bus 8、Train 5、Subway 4、Tram 4 | 现状线路参照；Passenger、Usage 等属性不能直接当作完整 OD 或连续流量 |
| `Zoning_Boundary.shp` | 33,333 面；含 Name、Color、Object、Zoning | 游戏分区单元；不能直接等价为本工具规划地块或 TAZ |

**关键事实及工程含义**：

- 样例 GeoTIFF GeoKey 为 EPSG:32631；Shapefile 的 `.prj` 同为 WGS 84 / UTM zone 31N，线性单位为米。保留其投影和实际仿射变换，不凭文件名推定其他数据同样如此。
- 两个栅格在标签中均声明 NoData 为 `1.70141e+038`。这是有限浮点数，因此单独使用 `isfinite`/`isnan` 判断无效值是不够的。Depth 有效像素数为 3,250,910；DEM 为 16,777,216。
- Carto 作者文档说明 Depth 中非正水深的陆地区域可写为 NoData；Elevation 相对于游戏原点，而非海平面。[R2] **只有确认数据覆盖完整、没有缺测后，Depth 的 NoData 才能按该语义归为非水域；一般 GIS 数据的 NoData 仍应视为未知。**
- 样例没有独立水域面。`Network` 中的 Waterway 是航道网络，不是水域边界。本工具须从 Depth 正有效像素生成水域，不能拿航道缓冲替代水体。
- DEM 和 Depth 具有不同像素大小，不能按数组行列直接叠加。先校验投影、仿射和覆盖范围，再执行显式重采样。
- 样例中心线是二维 PolyLine，桥隧信息位于 `Form` 等属性。`Elevation` 属性不能替代逐顶点高程；二维交叉不等于拓扑连通。
- 样例没有完整的稳定实体 ID、车道逐向结构、转向限制、信号配时、交通 OD 或时间序列。以上数据采用补充参数、推断及人工确认，必须标记来源。
- `.cpg` 声明 UTF-8；本次 DBF 字符字段严格 UTF-8 解码检查未发现非法字段值。不得因终端显示乱码而擅自转码原文件。
- `tifffile` 在枚举页目录时出现 `invalid page offset` 警告，但首波段成功读取。P0 必须用拟采用的 GDAL 驱动与 QGIS 复核读写兼容性；当前既不能据此宣称文件损坏，也不能宣称全部兼容。

### 1.3 必选、可选 GIS 与非 GIS 参数契约

Carto 官方支持 GeoTIFF 栅格及 Shapefile/GeoJSON 矢量，几何和字段可由用户配置，因此导入器采用“能力发现 + 版本化适配”，不要求全部可选字段永远存在。[R1][R2]

| 输入角色 | 是否必选 | 接受形式及语义 | 缺失时行为 |
|---|---|---|---|
| 地形 `terrain_elevation` | **必选** | Carto Elevation GeoTIFF，或经显式校验的等价 DEM；须有可解析的单位、栅格定位和无效值规则 | 拒绝启动规划计算，保留导入诊断 |
| 水域 `water_extent` | **必选** | 优先 Carto Depth GeoTIFF，经无效值处理得到水域；也可接受已明确 CRS、有效范围的水域面 | 拒绝启动规划；不允许只靠单一高程阈值猜测水域 |
| 航道水深 `water_depth` | 条件能力 | 输入为 Depth 时随必选水域一起获得；若仅有水域面则可能缺少 | 允许水域与陆地规划；港口/航道可做几何筛选，但水深可行性不可标为通过 |
| 项目/地图范围 | 可选 GIS、必需的派生配置 | 优先 Area 中 MapTile 合并；缺少时从有效 DEM 覆盖与用户 ROI 明确确定 | 展示采用的范围与裁切影响，不增加第三个强制 GIS 图层 |
| 现状用地、建筑、人口/就业、设施 | 可选 | Zoning、Building、POI、Area | 转入新城情景；以用户目标人口、就业、容积率等非 GIS 参数估算 |
| 现状道路、轨道、航道、公交线路 | 可选 | Network、Route | 新建候选网络；外部连接采用明确的情景网关，而非宣称识别出真实连接 |
| 自然资源、保护区、景观、土壤等 | 可选 | 用户提供的补充图层或绘制约束 | 仅输出保护候选与不确定性，不伪造生态属性 |
| 世界地形/水深 | 可选 | World Elevation/World Depth | 外部走廊研究限制在已知范围；不推断未知世界段可施工 |
| 规划参数 | **非 GIS 配置** | 目标人口/就业、开发强度、分区街区尺度、峰时系数、设计速度、资产尺寸、船型/车辆参数等；用地情景参数编辑权限按 1.5 执行 | 提供版本化情景默认值，并要求关键假设显式确认 |

**两类运行模式**：

- **新城规划模式**：只有 DEM + 水域即可进入全部模块的方案生成；需求与设计参数来自已标记的情景假设。关键数据不足的专项校核返回“待补资料”，而不是静默通过。
- **既有城市改造模式**：可选现状数据用于需求背景、现状约束和规划比较，不将游戏观测校准或新增遥测作为前置条件。默认保留现状，只有用户明确的分区拆迁许可可形成拆迁候选。

### 1.4 数据标准化、清洗与质量门禁

**推荐目录分层**：原始只读快照 `raw` → 规范化数据 `normalized` → 分析派生层 `derived` → 情景 `scenario` → 方案结果 `results` → 交换成果 `exports`。

1. **登记与快照**：记录城市名、游戏版本、Carto 版本或 unknown、导出设置、导出时间或 unknown、文件校验值、缺失附件。建议游戏暂停后成套导出；无法证明同一时刻的数据标记为快照一致性未知。
2. **输入解析**：GeoTIFF 读取 CRS、仿射、像素大小、波段类型、NoData；Shapefile 检查 `.shp/.shx/.dbf` 配套、`.prj/.cpg`；GeoJSON 单独解析坐标体系，不因同一目录而假定与栅格相同。
3. **坐标统一**：分析采用以米为单位的项目 CRS；保存原始 CRS、变换与游戏坐标映射。缺少 CRS 时停止自动对齐，允许用户明确映射，不“猜测成功”。
4. **栅格规范化**：先构造有效掩膜；连续 DEM 可采用适当连续插值；水域分类掩膜用最近邻，水深插值仅在已知水体内部执行，禁止跨岸线污染。保留原始 3.5/7 m 细节；粗分辨率只服务于候选搜索，不冒充提高精度。
5. **陆水识别**：标准水域为覆盖有效且水深为正的区域；近零水深建立可配置不确定带，不凭任意阈值消灭浅水。陆地为研究范围中已知非水域部分；未知覆盖区单列。
6. **几何与属性**：检测空几何、自交、多部件和重复记录；修复前后保存差异；分类字段按枚举/逗号分隔标签解析；未知类型入隔离区。`Addr_dist` 等字段通过显式映射进入规范名，保留原名。
7. **道路拓扑**：按 Object/Category 分模式；Direction 转为有向边；平面交叉结合端点、Form、层级、可用高程及人工确认建图。桥隧不可仅因投影交叉而连通。Lane、Limit、Elevation 的逐向/单位/基准含义列入适配验证。
8. **质量输出**：阻断项、可降级项、警告分别出报告。有效值范围、陆水面积守恒、投影误差、未解析类型、孤立组件及连接歧义可在地图定位。

#### 1.4.1 P0-02：真实 Carto 数据导入与坐标/栅格语义验证

P0-02 承接 P0-01 的统一实体、权限及禁拆契约，为后续理论需求、陆水识别和约束计算提供可追溯的数据底座。历史讨论明确七项工作：GDAL/Rasterio 复核 GeoTIFF；DEM/Depth 分辨率与对齐；Shapefile 字段、编码和几何；现状图层与 PlanningZone 关联；资料不足表达；桥隧形态字段；真实数据适配报告。本节的数据规格继续适用；本版的有限实现及真实数据结果分别见 1.4.3、1.5.4、2.4.5，不以导入结果替代完整规划验收。

| 环节 | 输入与处理结论 | 拟输出及阻断边界 |
|---|---|---|
| 源文件登记 | 原始样例只读；逐文件计算校验值，登记游戏/Carto 版本、导出设置、配套文件及来源；未知信息保留 unknown | DatasetManifest 与快照一致性诊断；不根据文件名或同目录推定版本、CRS 一致 |
| 驱动与结构复核 | 采用已有 GDAL/Rasterio 读取 GeoTIFF 元数据及代表性窗口；矢量先查图层、字段、几何类型和编码；区分元数据可读与像素/要素可读 | 驱动与依赖版本、读取范围、成功/失败和原始警告；历史 invalid page offset 需独立复核，不能凭旧审计判损坏或全部兼容 |
| 坐标与单位 | 分别核查每个输入的 CRS、轴向、水平单位、仿射及空间范围；高程单位、竖向基准和游戏映射单列 | 共同米制 space_id、转换记录与证据；缺少必要 CRS/单位时阻断对应空间计算，不静默赋予 EPSG |
| 栅格有效性 | NoData 标签、波段掩膜和非有限值联合判断；有限浮点哨兵按实际数据类型处理；有效零值/负值不自动归无效 | terrain_valid_mask、depth_valid_mask、覆盖及有效值统计；不把 isfinite 检查等价为完整 NoData 处理 |
| 格网对齐 | 显式选定目标 CRS、仿射、分辨率和研究范围；检查原始格网偏移及覆盖；DEM、水深和分类掩膜分别选择重采样策略 | 对齐参数、重采样方法、边界影响与派生层；不按数组下标直接叠加，不把细化格网称为增加源数据精度 |

必选输入继续为 DEM + 水域；Depth 与明确 CRS/覆盖的水域面是水域输入的替代路径，不额外强制建筑、道路、Area 或 Zoning。只有水域面时可支持陆水几何分析，但水深依赖的港口/航道校核保留资料不足。现状数据缺失仍可采用已标记假设的新城情景，不得因此宣称无建筑、基础或地下障碍。

#### 1.4.2 格网、覆盖与质量判定口径

目标格网和 ROI 必须写入规范化元数据；原始分辨率及仿射保留在源清单。连续 DEM 可采用明确的连续插值，分类掩膜采用最近邻；水深处理须受已知水域与有效覆盖限制，不跨未知区或岸线补造有效值。不同分辨率的源数据必须先按共同空间范围定位，再对齐派生结果。

在同一 ROI 和面积口径下，水域、已知非水域、语义未知应互斥且覆盖研究范围；分别检查掩膜计数与面积守恒。像元面积由实际仿射确定，边界裁切及数值容差的口径随报告记录，不凭不同格网的数组数量比较面积。近零水深的不确定带配置单列，不能用任意阈值消除浅水。高程有效性、陆水类别和专项能力分别报告，避免一种检查通过掩盖另一种资料缺口。

导入质量状态采用“阻断/可降级/警告”，成果状态沿用“候选/待核实/未校核/校核通过/资料不足/无可行方案”。关键坐标或覆盖语义缺失属于资料不足；明确非法输入应报告输入错误；只有已知约束经求解证明不可满足时才可报告无可行方案。P0-02 不承担完整三维求解，不能把导入成功标为净空或游戏可建造性通过。

#### 1.5.1 已验证的数据与权限门禁

P0-01 原型位于 `prototypes/p0/contracts.py`，仅用于需求验证，不是正式 GIS 工程或完整计算框架。构造/导入拒绝无效或空的二维多边形、重复主键、重叠分区、Z 坐标混入、字符串拆迁布尔值、非正街区尺度及非法数值。不可变数据类使旧快照保持不变；`frozen` 不替代入口权限校验。

住宅/商住混合可覆盖情景，纯商业、工业、办公、公共服务、交通、保护及其它非住宅禁止覆盖与用户默认；输入不能自行声明 `editable=true` 提权。类型转为纯非住宅时停用住宅覆盖。用户默认和分区覆盖只能使用系统默认架构中已有键，拒绝重复参数、未知字段、非有限或不合法数值。测试使用 synthetic 数值，不能转成正式游戏默认。

非住宅街区尺度和拆迁开关仍可修改；非住宅情景只读不代表其理论需求为零。商住混合应保留住宅/商业构成，局部修改不能更改其它纯商业默认；物理字段和构成计算将在 P0-03 验证，不将权限原型当成已完成出行生成。

#### 1.5.2 接口与来源追溯

拟定任务输入包含 project_id、scenario_id、input_revision、module、parameters、random_seed；输出包含 job_id、status、progress、diagnostics、artifacts。已有 P0 原型只提供同步契约函数和显式版本拦截，不宣称完整作业管理已实现。

所有空间输入使用同一明确米制坐标空间标识，竖向向上为正。P0-01 只验证 space_id 一致，不验证 CRS、单位、游戏映射或三维安全。Shapely 的平面相交不用于证明立体净空；原型显式拒绝 Z 线形/足迹，竖向信息单列。

来源区分 observed、user、inferred、assumed。导入生成项目主键并保留源记录号，跨快照匹配需冲突确认，不把记录号/坐标哈希当作游戏稳定实体 ID。未来缓存键须包含输入、参数、规则和模型版本；旧结果不能覆盖新方案。

#### 1.5.3 P0-02 字段适配、实体关联与资料不足契约

适配按“发现源字段 → 版本化映射 → 规范值及来源 → 质量诊断”处理；下面为持续适用的数据设计；已实现的样例适配子集、矢量诊断及资料不足边界见 1.5.4，不将原型称为完整导入框架。DatasetManifest 拟补充数据角色、源图层/波段、驱动版本、原始/目标 CRS、水平/竖向单位、轴向、仿射、有效覆盖、NoData 策略及转换记录；实际字典与工程格式另行版本化，未知信息不得伪造为默认值。

现状对象与唯一 PlanningZone 的空间关联须列出所有相交分区；边界歧义、未匹配对象和跨区对象分别诊断，不只用质心所在分区裁决拆迁。关联后继续执行 P0-01 的最严格拆迁权限，权限未知按禁拆/待核实处理。原始快照不变；几何修复、字段推断和人工确认均保留差异及 observed/user/inferred/assumed 来源。

字段映射只把源资料转为规范输入，不放宽 D5 参数权限、D7 禁拆地下裁决或交通方式白名单。导入 editable 标记不能提权，排除方式可作为不参与计算的背景；未知敷设形态不能自动按地表处理。P0-02 需为后续三维校核暴露资料缺口，不能从二维中心线或导入成功推导完整地下可行性。

### 1.6 数据流与跨模块迭代

```text
Carto 导出 + 可选补充图层 + 显式规划参数
    → 数据适配/质量门禁 → 米制项目坐标与规范数据底座
    → 地形派生/陆水与硬约束
    → M1 唯一 PlanningZone（用地分区=TAZ）↔ 理论需求生成
    → M2 四阶段法/外部网关/分级路网
         ├→ M3 地块出入口/内部组织/停车
         ├→ M4 海运铁路外部走廊/地铁/站港枢纽
         └→ M5 公路入城接点/TIA/立交匝道
    → 共享评估与约束复核 → 用户编辑/锁定 → 增量重算
    → GIS 成果 + 方案比较 + 假设与可行性报告
```

**必须显式实现的反馈**：公交服务改变方式划分，重新影响道路需求；停车与出入口改变局部需求/转向；立交接点改变外部交通分配；路网用地与交通可达性反向影响 M1。采用有界外层迭代、松弛与明确停止规则；超时/不收敛保留候选和残差，不无限循环。

用户修改分区街区参数只使相关可变几何、连接及需求依赖失效；交通分配可能全网更新，但不等于全城几何重建。P0-01 已验证不可变快照和旧 revision 拒绝，完整编辑锁定与缓存失效链尚待集成验证。

### 3.2 M1：用地规划

**完整能力**：陆地识别 → 城市用地/自然保护区区分 → 地形分区 → 自动功能分配 → 用户变更。

1. 基于规范水域/未知掩膜得到陆地；建立岸线、不确定带、禁止开发区与用户保护范围。
2. 从 DEM 派生坡度、坡向、局部起伏、相对高差和地形连通性；对地形适宜性进行栅格评分与区域合并，剔除碎小片，生成可开发分区候选。
3. 自然保护区采用“用户指定的硬约束 + 可解释的保护建议”双轨。缺少生态资源图层时降低结论等级，不把地形自动分区当成生态识别。
4. 按功能配额、建设强度、地形成本、可达性、环境冲突和连续性构造分配模型。先用规则/多准则排序保证可行，再以 MIP/局部搜索改善成本；权重归一化并保存。
5. 保持规划用地与游戏 Zoning 的映射表，混合用地、公共设施和保护用地可表达；不能强行把所有规划功能塞进单一游戏分区枚举。
6. 用户可改宏观边界和功能、街区参数及交通设施，并锁定要素；住宅及商住混合情景强度按 D5 开放，其余情景固定默认。硬约束不得自动解除；不摆放普通非交通建筑。

**产物**：陆/水/未知、开发/保护及候选区、地形分区、功能用地、人口/就业推估、指标与冲突报告。

**难点与实施承接**：P0-01 已完成同一 PlanningZone、合法参数覆盖、默认继承和类型变化校验；并未实现自动分区/功能分配。配额/保护/地形无解输出冲突，不挤占保护；住宅可用多个用户情景，其它非住宅固定系统默认，不把 synthetic 默认或容积率当作游戏事实。

### 3.3 M2：路网规划

#### A. 唯一 PlanningZone 与逐区街区尺度

用地与交通共同使用同一 PlanningZone 边界，参考河流/铁路屏障、地形、宏观功能和可达性生成，但不得再划一套独立 TAZ。源行政区和游戏 Zoning 只是参考。净街区长宽/尺度范围、方向、支路间距、布局偏好及锁定都在同一实体保存，支持默认继承和逐区覆盖。

地形方向场/约束网格、局部路段连通和多边形化生成派生街区，不生成普通建筑。相邻区共享高等级道路和边界接口，支路渐变接顺。尺度是软目标，保护/禁拆/资产/锁定为硬条件；本区参数修改不得覆盖其它区几何。

P0-01 只验证净尺度、不可变快照、几何合法性和非住宅几何不被权限误锁；街网生成、边界接顺和全网交通反馈尚待实现。

#### B. 交通规划四阶段法

四阶段是出行生成、出行分布、方式划分、交通分配；共享 LOS/广义费用反馈，不能把“画路网 + 最短路”称为完整四阶段法。[R10]

1. **生成**：分目的、分时段，基于居民/就业/设施或未来开发量构造产生量 $P_i$ 和吸引量 $A_j$；外部—内部、内部—外部、外部—外部过境及区内出行分别记录。缺失现状时使用明确的情景系数。
2. **分布**：双约束重力模型或等价熵模型，迭代平衡产生/吸引量；用旅行时间/广义费用作为阻抗；无路可达与跨水不可达需求不得硬塞给虚构道路。
3. **方式划分**：规则初值 → 多项 Logit 候选，仅考虑道路小汽车、公交、地铁、客运铁路和客运海运等白名单方式，以聚合接驳/固定转接成本衔接；无服务方式不能分配需求，不生成步行/骑行接驳、有轨电车、出租车或内部航空网络。机场是外部 OD 网关，仅分配地面段且防重复计数。
4. **分配**：道路按车次与车型处理，人次向车次转换显式使用乘员率等参数；静态用户均衡采用 BPR/FW 类方法，公共交通按含接驳/候车/换乘的广义费用分配。[R6] 静态分配不用于直接估算队列溢出。
5. **反馈与停止**：公共交通/道路方案变动后更新阻抗和方式需求。外层迭代设置次数、时间与变化量阈值；保留最后可行方案和残差，不能只看几何稳定就宣称需求收敛。

候选需求模型：

$$
T_{ij}=a_i b_j P_i A_j f(c_{ij}),\qquad
\sum_j T_{ij}=P_i,\quad \sum_i T_{ij}=A_j.
$$

候选道路阻抗模型：

$$
t_a=t_a^0\left[1+\alpha_a\left(\frac{v_a}{C_a}\right)^{\beta_a}\right].
$$

**变量定义**：$T_{ij}$ 为分时段出行量，$P_i/A_j$ 为产生/吸引量，$a_i/b_j$ 为平衡系数，$c_{ij}$ 为广义阻抗，$f$ 为阻抗函数；$t_a^0/t_a$ 为自由流/拥堵旅行时间，$v_a/C_a$ 为同单位流量/容量，$\alpha_a/\beta_a$ 为待校准参数。所有参数均版本化；不直接套用现实默认值宣称符合游戏。

#### C. 外部连接与四级路网

- 现状模式：在项目边界/游戏外部网关、道路类别和连通图上识别连接候选，最终由适配验证或用户确认；普通悬挂端点不自动当作外部连接。
- 新城模式：将边界候选、外部道路方向和外部 OD 作为情景输入；缺少世界地图只优化研究范围内部分，标为假设网关。
- 候选路线采用成本栅格和方向/纵坡约束的 A*/最小成本走廊；需要曲率时引入方向状态与后续线形优化，而不是只运行普通像素最短路。
- 公路、主干路、次干路、支路分层生成并联合校核。类别由服务功能、可达性与需求建议，不只由现状 Category 或车道数决定。
- 桥/隧道按资产、地形和几何约束建候选边；水体不能被普通地面边穿透。不可拆迁对象控制区先强制仅隧道，再算成本，不能用高架软惩罚替代硬禁令；隧道无解或缺资料显式返回（3.6）。

**产物**：TAZ 与逐区参数、完整 OD 与方式需求、外部网关、四级道路、节点/转向、流量/饱和度/不可达与成本报告。

**难点预案**：网络设计为组合优化问题，首版采用分层候选生成 + 有界局部搜索，并输出多方案而非承诺全局最优；无完整需求观测时输出敏感区间。对无法收敛的模式反馈使用松弛和固定已确认供给的分阶段方案比较。

### 3.4 M3：内部道路规划

模块完整覆盖出入口、内部车行组织、配建和公共停车，不生成被排除的步行/骑行微循环。

1. 沿合法边界/道路等级生成出入口，筛选接入权限、路口/匝道影响、坡度、车辆包络、可达性和排队储存；受控公路不能直接任意开口。
2. 构建车行有向和转向/冲突图，组织单行、服务车辆、装卸和停车搜索，不把所有需求接到单个质心连杆。
3. 按分区功能、时段与固定/合法可编辑情景推算停车需求；同时规划配建、公共停车容量/位置和共享峰值。慢行接驳不建网，必要服务关系用聚合成本表示。
4. 先检验静态可达、冲突和存储，再验证局部微观车行/信号/回堵方案；SUMO 为候选，数据缺失用明确假设，不冒充游戏 AI。
5. 向 M2/M5 回传接入、转向、停车搜索交通；不得把停车仅作为无需求影响的图标。允许交通设施包络，不布局普通建筑。
6. 道路几何和用户修改共用 D7 政策裁决。P0-01 的三形态/禁拆/资料不足原型是前置门禁，不是已完成出入口、停车或微观组织。

输出入口合法性、内部车行/转向、服务组织、停车时段供需及运行报告。无解给出入口/尺度调整建议，不凭空增开入口或自动删建筑；缺库存/强度以默认或假设标记。

### 3.6 M5：公路入城规划

#### A. 连接点选址

在过境公路走廊与城市主干体系之间生成候选，综合服务覆盖、外部/过境 OD、主线与城市路网负荷、相邻接点影响、地形、用地与建设成本。采用候选组合搜索/MIP 与有界网络重分配，避免以“离市中心最近”作为唯一标准。保留过境与入城流的分离及合理绕行。

#### B. TIA 交通影响评价

TIA 按统一预测年份/时段/发展情景，至少比较：现状或基线、未来无建设、建设方案、建设加改善措施；无建设与建设方案保持相同外生发展假设，单列是否考虑诱导需求。研究范围依据受影响走廊、相邻路口和回堵传播设置，而不是固定圆形缓冲即结束。[R12]

流程：场景需求 → 接点与转向分配 → 主线/匝道/城市道路容量筛查 → 局部仿真 → 改善措施 → 再评估。输出流量/饱和度、旅行时间、延误、95 分位排队、储车长度/回堵风险和网络可达性；安全仅提供冲突风险代理，未校准时不预测事故率或法定 LOS 等级。

资料不足时输出基于假设的规划级 TIA、敏感区间与待补清单；没有观测不伪造校准报告。

#### C. 立交与匝道几何

1. **拓扑模板**：首版参数化支持与业务场景匹配的有限模板，例如菱形、喇叭形和定向衔接；按各方向交通关系生成，不仅摆放图形。
2. **平面线形**：直线/圆曲线/缓和段或明确的游戏曲线适配；检查设计速度、最小半径、曲率连续性、分合流位置与所需空间。
3. **纵断面**：利用 DEM 和道路/轨道结构层，生成受纵坡、竖曲线、净空及接顺约束的高程曲线；二维穿越线不能自动变成可行立交。
4. **衔接运行**：显式配置加减速段、织入/织出、车道及汇入关系；实际长度等采用已验证的游戏参数/用户标准，而非写死未经验证的现实值。
5. **占地与结构包络**：输出道路面、结构/边坡预留、冲突和简化土方指标；不当作结构设计。
6. **最终复核**：对平滑、模板拉伸和用户拖动后的最终几何重新检查；若不能满足约束则降为不可行候选并说明原因。

现实方法上，水平与竖向线形、匝道间距、视距和分合流应联合考虑，参考 FHWA/NCHRP 的工程方法；具体约束值由游戏适配与用户确认的设计标准决定。[R13][R14]

**产物**：连接点、转向需求、TIA 报告、立交有向拓扑、匝道平面线形/纵断面、占地与约束校核、游戏资产映射/未验证项。

**难点预案**：游戏曲线、道路预制资产和净空约束不清晰时，P0 做有限实际建造/对照试验，记录版本与参数。若无法满足几何或运营要求，尝试其它接点/模板；不通过放宽硬约束强行给出“可建造”方案。


#### D. 共用 D7 现状冲突门禁：P0-01 已实现的政策契约

M2 道路、M3 内部道路、M4 轨道和 M5 立交匝道共用形态裁决，不靠极高高架成本限制违规。PlanningZone.allow_demolition 默认为 false；跨区对象须完整被分区覆盖且所有区明确允许，才可提出拆迁。任一禁拆、缺匹配或权限不完整不得默认允许；允许拆迁也不删除输入或布局替代建筑。

流程为：输入 revision/米制 space_id 一致 → 独立硬保护 → 候选完整控制半宽的平面包络 → 现状足迹/缓冲交叠 → 分区权限 → 强制地下及资料门禁 → 局部地下界/无解判定 → 留给后续完整几何求解器。

在禁拆控制区剔除 SURFACE 与 ELEVATED，仅允许 TUNNEL。名义高程高于楼顶不能使交叠消失；不允许先抬高后重新判定，也不以自动横向绕行替代当前冲突区的地下裁决。用户另选不进入控制区的走廊为独立候选。

| 政策状态 | 原型输出含义与禁止误读 |
|---|---|
| POLICY_CLEAR | 此快照未触发禁拆，不是净空、纵坡或工程验证通过 |
| TUNNEL_REQUIRED | 只能地下且 lower_only，不表示已求出可施工隧道 |
| DATA_INSUFFICIENT | 现状覆盖/分区/基础不足；已有冲突仍地下-only，不标通过 |
| NO_FEASIBLE_SOLUTION | 资产不支持地下、已知地下范围空或其它硬冲突；不回退地表/高架 |
| STALE_INPUT | 输入 revision 过期，不作为当前结果发布 |

局部标高按竖向向上为正，地面高程/基础底界资料充分时：

$$
z_{c,\max}=\min\left(z_g-d_{cover},\;z_f-d_{clear}\right)-\frac{H_{outer}}{2}.
$$

变量：$z_{c,\max}$ 为隧道中心标高上界，$z_g$ 为地面标高，$z_f$ 为受保护基础底界，$d_{cover}$ 为最小覆土，$d_{clear}$ 为基础安全间距，$H_{outer}$ 为隧道完整外高度；全部使用同一米制竖向基准和版本化参数。若最低允许标高高于任一局部上界，地下范围为空。该不等式是局部门禁，不能单独证明坡度、入口或地下设施不冲突。

高程求解器后续必须遵守 collision_escape_direction=LOWER_ONLY，禁拆区不能向上脱困；出入口及升降过渡在保护包络外，离开冲突区后可合法接回地表。地下仍须避开基础/地下设施、满足覆土/净空/坡度/竖曲线/资产，且无生态保护豁免。

本次 43 合成案例覆盖地表/屋顶高架/已为隧道、完整幅宽/安全缓冲、跨区最严格/全允许、部分关联、基础未知、资产不支持、地下范围空/边界、保护、旧 revision、数据类型及原对象保留。尚未实现完整纵坡/竖曲线求解、隧道入口出口、桥墩/地下设施三维碰撞和游戏内建造验证；不能把 lower_only 标记当成求解能力。

用户拖动、平滑、资产替换或工程导入后须最终完整包络复核。权限/边界/现状/规则改变使相关几何/评价失效；锁定成果违法时保留并标无效，不自动修改或豁免。旧作业不能覆盖新版本。这些全链集成是后续任务，P0-01 只验证显式版本拒绝与不可变输入。
