## 1.【D 系列决策落位清单】

**必选 GIS 输入保持不变**：地形 DEM/高程与水域。水域可由正确处理 NoData 的 Carto Depth 提取，也可来自明确坐标和有效范围的水域面。建筑、设施、现状路网等其余 GIS 均为可选；不存在输入图层不等于证明地上地下没有障碍。

### 1.2 D1：逐分区街区参数与人机协同

**采用推荐方案：参数驱动生成 + 手工修订/锁定。**

- 每个分区（即 TAZ）独立保存目标街区长/宽或尺度范围、布局方向、道路形态偏好、支路间距及接入组织等几何/交通参数；可继承项目默认值，但局部设置不能覆盖其他分区。
- 用户看到的街区尺度以道路边界之间的净尺度为口径；算法根据道路宽度转换为中心线间距。地形复杂或非矩形区域以目标范围/统计尺度解释，而非假装精确矩形。
- 街区尺度为软目标；硬保护、D7 避让、游戏物理约束及人工锁定优先。硬条件冲突时返回诊断，不强行拉成规则网格。
- 手工修改道路/节点、出入口和局部组织后，可锁定其几何或指定配置。人工编辑与导入方案仍必须接受硬约束校验。
- 局部重算以依赖影响为边界：本区可变几何及必要衔接更新；其他分区已锁定几何保留。交通分配可能需要全网更新，不等于全城道路几何重新生成。
- 不在街区内布局住宅、商场、工厂等普通建筑。

### 1.3 D2：交通导向的宏观用地规划及统一实体

**采用推荐范围：保留原 M1 完整能力，但只做宏观功能分区，不做普通建筑布局。**

- 保留陆地识别、城市开发/保护候选、地形分区、宏观用地功能自动分配和用户修改。
- 分区功能作为交通产生/吸引模型的输入；功能修改合法性与 D5 情景参数编辑权限是两个不同维度。
- 可规划道路、轨道、出入口、站港枢纽及停车等交通设施的交通空间和包络。
- 严禁生成、移动、旋转、摆放住宅、商场、工厂、学校、医院等普通非交通建筑；严禁以“拆迁允许”为由自动重建或重新布局这些建筑。
- 已有普通建筑仅作为背景、需求参考和现状障碍；其原始 GIS 快照始终保留。

**强制概念等价：用地分区 = 交通小区 TAZ。**

系统仅存在一个规范实体 `PlanningZone`，使用唯一 `zone_id`：

| 属性组 | 同一实体上的字段 |
|---|---|
| 空间/功能 | `zone_id`、规范边界 `geometry`、`land_use_type`、有效版本 |
| 街区 | 街区尺度、道路布局方向/形态、局部锁定与继承关系 |
| 情景 | 情景参数、覆盖值来源、默认值版本、编辑权限 |
| 拆迁 | `allow_demolition`（默认 false，用户按分区显式设置） |
| 交通 | 理论产生/吸引量及其场景/时段关联；OD 的 origin/destination 直接引用 `zone_id` |

**数据不变量**：

1. 不创建独立的 `LandUseZone` 与 `TAZ` 几何、属性或生命周期，不维护二者映射表。
2. UI 可显示“用地分区（TAZ）”，但这是同一对象的名称，不是两个对象的一一关联。
3. 分区分割、合并和边界修改只能由一次规范操作修改同一实体集合；随后显式使其需求、街区和现状关联失效/重算。
4. 源行政区、源游戏 Zoning 单元等只作只读输入，不等价为第二套规范分区。为识别陆水/保护而生成的掩膜是约束数据，不是独立 TAZ 集合。
5. 街区是道路围合的派生几何，建筑是输入障碍，设施是交通对象，均不构成另一套“用地分区”。
6. 规范分区原则上为无重叠有效分区；边界歧义、空缺及合并/分割影响必须诊断，不能制造两个相互矛盾的拆迁权限。

### 1.4 D3：原生 GUI 与运行架构

**采用推荐方案：Qt/PySide6 原生桌面窗体、菜单、对话框及停靠面板；允许内部嵌入离线地图/指南视图。**

- GUI、项目打开/保存、规划编辑和成果浏览均在独立软件内，不要求用户打开外部浏览器。
- 允许内嵌离线 WebView/HTML 作为视图实现，但不因此转为在线网站；资源、图层和指南均随本地工程/安装资源提供。
- 本地模块化单体加后台计算进程；进程间本地通信，不默认要求 HTTP 服务、云后台或消息队列。
- 算法层采用 Python GIS/数值计算路线；具体依赖组合、版本、地图渲染器和封装方式是后续工程论证项，不假装本轮已验证兼容性。
- 所有参数权限和硬约束在计算核心执行；不能只在 GUI 按钮上做限制。
- 用户主动打开外部链接可作为可选动作，查看指南和核心规划功能不依赖联网。

### 1.5 D4：方式白名单与机场节点

| 对象/方式 | 首版处理 |
|---|---|
| 城市道路小汽车客运 | 纳入理论需求及道路分配 |
| 城市公交客运站、枢纽和线路供给 | 纳入选址、接驳及交通评价 |
| 地铁、客运铁路、客运车站和轨道走廊 | 纳入线网/选址/几何与客流模型 |
| 客运港口、海运外部走廊及客运航道 | 纳入选址/走廊及能力校核 |
| 公路货运 | 纳入独立车型/货运需求、内部组织和 TIA |
| 有轨电车、出租车 | 明确排除规划、需求方式划分和分配 |
| 步行/骑行慢行微循环及接驳 | 明确排除网络生成、路线求解、设施设计及方式分配；不得借“客运全场景”重新加入 |
| 航空内部客运、内部航线网 | 明确排除航空网络与内部航线建模 |
| 铁路、水运、航空货运 | 明确排除需求、设施货运能力及物流模型 |
| 机场枢纽 | 仅作为宏观外部产生/吸引点（OD 端点）与地面多式联运接驳枢纽 |

**机场模型契约**：

- 机场使用一个节点身份 `AirportGateway` 表达，不为其建立内部航空网络或航班/航线分配。
- 机场定位可来自已有 GIS/用户指定位置；允许规划与本工具已纳入的道路、公交、地铁或客运铁路的地面连接和接驳设施。
- `AirportGateway` 不是新建 TAZ：其通过 `host_zone_id` 引用实际所在的 `PlanningZone`，在 OD 中作为带机场来源标签的外部端点/网关身份。
- 对已知机场节点，机场边界客流只计入机场网关；通向城市的同一批客流不得再同时从所在分区的一般功能产生量生成一次。
- 区域客流进入机场网关或由其离开，模型内部只分配其地面交通段；不构建跑道、航路、航站楼内部客流或航空货运。
- 站点服务与换乘可使用分区关联、固定转接时间等聚合关系；不得暗中构建被排除的步行/骑行接驳网络。
- 可选输入若含有排除方式，仅允许作为注明“不参与计算”的现状背景保存，不能进入首版计算白名单。

### 1.6 D5：情景参数权限、默认值与混合用地

**编辑白名单仅限：住宅用地；包含住宅的商住混合用地。**

| 数据/操作 | 处理 |
|---|---|
| 住宅分区情景参数 | 可编辑，允许合法范围内的分区覆盖值 |
| 包含住宅的商住混合分区情景参数 | 可编辑该类型允许的情景字段；保留住宅/商业构成及来源 |
| 上述两类的默认情景值 | 允许用户修改并保存为用户默认；保留出厂默认和用户默认版本 |
| 纯商业、工业、办公、学校、机场、其他非住宅类型的情景参数 | 固化为项目所采用的系统默认版本；前端只读，不提供编辑入口 |
| 非住宅系统默认参数 | 不开放用户编辑；不得通过导入工程、内部接口或隐藏字段绕过 |
| 分区功能、街区尺度、道路几何、拆迁权限 | 不是 D5 的“情景参数”，依各自 D 项规则编辑；不能错误地将非住宅分区的街区尺度/拆迁开关也锁死 |

**核心权限规则**：

- 每次取值、更新、保存、导入和重算都按实际 `land_use_type` 判定权限，不信任输入中的 `editable=true`。
- 非住宅实际情景值必须来自 `SystemDefaults[type, version]`；非法覆盖拒绝并定位，不静默接受。
- 住宅/商住混合采用明确的“系统出厂值 → 用户默认值 → 分区覆盖值”继承关系，并记录哪些参数仍在继承。
- 用户修改默认值时，仅使相应合法类型的继承分区失效/重算，不覆盖分区显式覆盖值或已锁定配置。
- 混合用地局部可编辑，不得反向修改全局纯商业默认或其它非住宅分区。必须拆分/标记模型中住宅与商业构成，避免出行重复计数。
- 分区功能变为纯非住宅类型时，清除或停用原可编辑覆盖值并使用系统默认；保留历史审计但不得继续生效。
- 非住宅类型的居民/就业规模、出行率等需求不能因只读而缺省为零；使用其固定默认和空间规模派生需求，并标为理论假设。
- 工业/商业/办公等公路货运参数固定默认，用户不能通过 D5 界面编辑；其道路和出入口仍可按其它规则调整。

### 1.7 D6：规划级空间校核与查看

**采用推荐方案：二维主地图编辑 + 纵断面图 + 局部三维校核查看。**

- 必须计算平面线形、纵坡/竖向接顺、道路/轨道/交通设施完整占用包络、立体净空与现状冲突。
- 三维计算不等于首版必须提供全城三维建模编辑器；局部三维视图用于解释冲突和显示地表/高架/隧道及包络。
- 不能只检查中心线或单个采样点；占用包络应考虑资产宽高、桥墩/隧道结构和必要安全余量。
- 原始建筑高度、地下基础或资产包络缺失时，明确数据不足或使用带来源的保守假设；无足够依据不能宣称真实三维安全已验证。
- 平滑、用户拖动、资产替换和连接修复后的最终几何都必须再次执行 D7 硬约束检查。

### 1.8 D7：敷设形态、拆迁控制与不可拆迁绝对红线

#### A. 默认形态与权限

- 路网与轨道的规划引擎支持 `SURFACE`（地表）、`ELEVATED`（高架桥梁）、`TUNNEL`（地下隧道）三种候选形态；具体资产仍须支持选用的形态。
- 输入有已建建筑/设施时，用户通过同一 `PlanningZone.allow_demolition` 设置分区拆迁权限，默认不可拆迁。
- 已建对象通过空间关联引用一个或多个分区。跨分区对象只要涉及任一不可拆迁分区即整体按不可拆迁处理；未匹配、权限不明或来源缺失按不可拆迁/待核实处理，不假设允许。
- 允许拆迁只是允许方案提出移除/改造候选，不自动删除源 GIS、不能实际拆游戏存档，更不能布局替代普通建筑。

#### B. 冲突触发范围

为了避免“桥梁升到楼顶上方所以三维不相交”的漏洞，判定分两层：

1. 用线路完整占用/控制包络的平面投影与现状实体足迹及安全缓冲检查交叠，得到必须受 D7 约束的冲突控制区；不能仅比较中心线。
2. 再进行实体及地下基础/结构的三维校核，判断地下解是否真正满足净空与基础避让。

**高架从不可拆迁建筑足迹上方跨越，即使桥面高于屋顶、没有发生严格的三维实体相交，也属于被禁止的绕避方案。**

#### C. 强制裁决

| 条件 | 可选形态/行为 |
|---|---|
| 不涉及不可拆迁建筑/设施，且其它约束允许 | 地表/高架/隧道按地形、资产和工程成本选择 |
| 现状对象可拆迁 | 可以评估拆迁相关的候选，但必须保留对象清单及其它约束校核 |
| 现状对象不可拆迁，线路进入其冲突控制区 | **仅地下隧道；地表与高架候选直接剔除** |
| 候选已经是高架但进入上述区域 | 仍须强制转为隧道候选，不得增加桥面高度脱困 |
| 隧道受基础/地下设施、覆土、净空、坡度或资产支持限制而不可行 | 返回无可行方案，不回退地表/高架、不自动改拆迁权限 |
| 基础埋深等关键校核依据缺失 | 返回资料不足；如展示假设方案，只能是标记待核实的地下方案，不得标为通过 |

该规则是可行域硬约束，不是“高架成本非常高”的软惩罚。M2 路网、M3 内部道路、M4 轨道与 M5 立交匝道共用同一裁决器；用户编辑、导入候选、平滑和重算均不能绕过。

#### D. 地下高程生成

取项目竖向坐标向上为正；在冲突控制区，隧道最高外包络必须低于受保护现状对象的地下保护底界并留足安全间距，同时满足地表覆土、纵坡、结构及其它地下设施约束。

- 碰撞求解只允许切换到地下形态，并向更低的候选标高搜索，禁止使用“抬高跨越”搜索动作。
- 建筑足迹上方的所有地表/高架解均禁止，不能靠先抬高再重新判定使禁令失效。
- 对地下隧道也不能允许实体穿透：必须避开基础、地下设施和已有隧道等保护包络，检查整个通道而非隧道中心线。
- 入口、出口及下降/上升过渡放在冲突控制区及其保护包络之外，长度需满足坡度和接顺。局部冲突的禁止抬高不表示整条线路永远只能下降；隧道驶离保护区后可合法接回地表。
- 路径算法不得在当前冲突位置自动用横向绕行代替“强制隧道”裁决。用户另外选择不进入该控制区的走廊是一个新的候选方案，不构成原冲突走廊的地下解。
- 地下不自动获得生态硬保护豁免。若已确认的其它硬约束禁止该位置穿越，仍须拒绝，不能用 D7 作为绕过 Q8 的依据。

## 2.【D7 现状冲突判定流】

### 2.1 基本流程

```text
新建/修改道路或轨道候选
  → 读取同一版本的分区、拆迁权限、现状对象、地形与资产包络
  → 检查独立硬约束（生态保护、已锁定工程、资产允许形态等）
  → 对完整线路包络执行现状空间查询
      ├─ 无现状实体控制区交叠：按其它约束评价三种形态
      └─ 有交叠：逐个现状对象获取关联分区及拆迁权限
           ├─ 所有关联分区均明确允许拆迁：保留拆迁候选/清单，继续校核
           └─ 任一不可拆迁，或权限未知：
                → 强制 allowed_modes = {TUNNEL}
                → 禁止地表穿透；禁止建筑上方高架跨越
                → 向地下标高生成候选，过渡段位于保护区之外
                → 检查地下实体/基础、覆土、纵坡、净空及资产支持
                     ├─ 依据不足：DATA_INSUFFICIENT
                     ├─ 无可行地下解：NO_FEASIBLE_SOLUTION
                     └─ 有解：暂存地下候选
  → 联合校核所有冲突区、过渡段及连接关系
  → 对最终平滑/编辑后的完整包络复核
  → 输出可行地下方案，或拒绝原因/待补数据；禁止非法回退
```

### 2.2 算法契约伪代码（说明性文本，不是本轮实现）

```text
DECIDE_EXISTING_CONFLICT(candidate, snapshot):
    assert snapshot.zone_entity == PlanningZone     # 分区就是 TAZ
    assert snapshot.revisions_are_consistent

    if violates_independent_hard_constraint(candidate):
        return NO_FEASIBLE_SOLUTION(reason)

    hits = query_existing_control_envelopes(candidate.full_swept_envelope)
    mandatory_tunnel_intervals = []
    demolition_candidates = []

    for object in hits:
        zones = intersecting_PlanningZones(object.footprint)
        demolition_allowed = zones_are_resolved_and_complete(zones)
                             AND every(zone.allow_demolition == true)

        if demolition_allowed:
            demolition_candidates.append(object.id)
            continue

        interval = affected_alignment_interval(candidate, object.control_envelope)
        mandatory_tunnel_intervals.append(interval)
        forbid(interval, SURFACE)
        forbid(interval, ELEVATED)                  # 即使能从屋顶上方跨越也禁止
        require(interval, TUNNEL)

    if mandatory_tunnel_intervals is not empty:
        if not asset_supports(TUNNEL):
            return NO_FEASIBLE_SOLUTION("当前资产不支持强制隧道")
        if critical_underground_envelope_data_unresolved:
            return DATA_INSUFFICIENT("基础/地下保护范围无法可靠校核")

        profile = solve_underground_profile(
            intervals = merge(mandatory_tunnel_intervals),
            collision_escape_direction = LOWER_ONLY,
            disallow_upward_overpass = true,
            portals_outside_protected_envelopes = true,
            constraints = cover + foundation_clearance + other_underground_objects
                          + grade + vertical_alignment + asset_limits
        )
        if profile is absent:
            return NO_FEASIBLE_SOLUTION("地下线形不可行；禁止改用地表/高架")
        candidate = apply(profile, candidate)

    if not final_full_envelope_check(candidate, snapshot):
        return NO_FEASIBLE_SOLUTION(reason)

    return FEASIBLE_CANDIDATE(candidate, demolition_candidates, assumptions)
```

**分支解释**：跨分区对象取最严格权限；任意禁拆不能被附近可拆分区覆盖。遇到多个冲突先合并/联合检查隧道控制区，不可分别求解后得到无法接顺的片段。缺地下资料和确实无可行解是不同状态；都不能自动尝试向上绕避。

### 2.3 硬约束验证、权限与缓存失效

- 修改分区边界、`allow_demolition`、现状包络、游戏资产或硬保护边界时，使有关候选、纵断面、三维检查及其评价失效。
- 新政策使已锁定几何不合法时，保留锁定几何供用户查看并标记无效，不自动修改它、也不将其锁定当成合法豁免。
- 旧作业在输入版本变化后不得把已失效的高架方案写回当前场景；验证版本一致性后才能发布结果。
- 缺少建筑/设施输入时，功能可运行，但三维现状冲突覆盖范围为“未知/未提供”，不得宣称整条线路已证明不碰建筑或地下基础。
- 方案输出分别记录：允许/强制形态、冲突对象、关联分区、拆迁许可来源、包络依据、假设、可行性状态和否决原因。

## 3.【需求收敛总结与下一步】

### 3.1 收敛状态

**Q/D 业务需求及重大设计边界已收敛，没有需要重新询问用户的 D 系列阻塞项。**

已确认并落实的核心结果：

3. 地形和水域必选，其他 GIS 可选；纯理论四阶段模型，无动态遥测前置条件。

8. 个人+AI 开发；旧团队工期无效；性能目标待未来 G0 实测。
