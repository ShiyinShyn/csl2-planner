## 1. 目录职责与格式

采用 UTF-8 JSON，结构版本暂定 `q03-draft-0.1`。目录仅记录来源、单项参数候选、未拆分字段组、假设和缺口；不保存用户默认、分区覆盖、工程状态或执行表达式。

Q 自有结构与 P 的 `ScenarioValues`、`DefaultCatalog`、未来 C-D 独立。校验结果只说明记录是否合法且自洽，不返回上述 P 对象、不把候选参数自动转换成计算输入。后续由 P 明确消费映射、实际用地权限、单位转换、批准记录和版本失效条件。

不新增依赖：后续可用 Python 3.11 标准库 `json`、`math`、`pathlib` 实现轻量检查。目录不执行脚本、导入代码、访问来源 URL 或解引用工程数据。链接存在性检查只针对仓库内静态来源文件。

### 1.1 顶层对象

以下各字段必需，所有对象采用封闭键集合：未知键拒绝，扩展必须升结构版本。可空与可空数组仅限下文明确情形；不通过丢弃字段兼容旧文件。

| 字段 | 类型与规则 |
|---|---|
| `draft_schema_version` | 字符串；本版仅接受 `q03-draft-0.1` |
| `catalog_version` | 非空字符串；每次内容变化更新，不仅靠日期区分 |
| `status` | 固定 `DRAFT`；不能改成 APPROVED 或注入 approved=true |
| `consumer_baseline_refs` | 非空对象数组，字段见 1.2；记录实际所据版本 |
| `sources` | 非空 Source 数组，字段见第 2 节 |
| `parameters` | Parameter 数组，允许为空；仅放语义已拆清的单项记录 |
| `inventory_groups` | InventoryGroup 数组，允许为空；未拆清项保留在此 |

`parameters` 与 `inventory_groups` 不可同时为空。两处 ID 各自唯一，并且全目录不重复；来源 ID 单独命名。空参数数组只表示尚无单项目录，不报告“参数完成”。

### 1.2 公用记录

| 对象 | 必需字段及含义 |
|---|---|
| BaselineRef | `path`（仓库相对文件路径）、`version`（非空字符串或 null）、`sections`（非空字符串数组）、`notes`（非空字符串）；版本未知时 notes 明确缺口 |
| SourceRef | `source_id`、`role`、`claim_locator`、`notes`，均为非空字符串；role 仅取 RULE、DEFINITION、VALUE、ASSUMPTION、TEST；locator 精确到支持该断言的位置 |
| Gap | `field`、`reason`、`next_evidence`，均为非空字符串；field 为记录内字段路径或 INVENTORY_SPLIT |

字符串 ID 用稳定 ASCII 标识，匹配 `[A-Za-z0-9][A-Za-z0-9._-]{0,79}`。一般说明可以中文。数组中 ID、枚举、路径/版本组合等标识项不重复。

SourceRef 的 role 不只是标签：引用规则或定义不能满足数值来源要求；引用测试不能满足生产候选依据。校验可检查关联和状态，不能判定原文是否真的支持断言，最终仍需人工核查来源位置。

## 2. Source：获取状态与版本验证分开

### 2.1 字段

Source 必需字段为 `source_id`、`source_kind`、`locator`、`source_version`、`retrieval_status`、`version_verification`、`notes`。

| 字段/对象 | 允许值与规则 |
|---|---|
| `source_kind` | PRODUCT_RULE、PROJECT_PLAN、LOCAL_CODE、LOCAL_GUIDE、GAME_OFFICIAL、ENGINEERING_REFERENCE、TEST_FIXTURE、THEORY_REFERENCE |
| `locator` | 对象：`kind`、`target`、`section`；kind 为 LOCAL_FILE 或 HTTPS_URL；target/section 为非空字符串 |
| `source_version` | 非空字符串或 null；文件存在不证明其具有版本号，未知写入 notes |
| `retrieval_status` | LOCATED_ONLY、LOCAL_READ、EXTERNAL_READ、UNAVAILABLE |
| `version_verification` | 对象：`status`、`game_build`、`model_version`、`asset_scope`、`method`、`evidence_locator`；后五项为非空字符串或 null |
| `version_verification.status` | UNVERIFIED 或 VERSION_BOUND_VERIFIED |
| `notes` | 非空字符串；说明局部阅读、未读原标准、无法访问、来源权利或其他证据限制 |

LOCAL_READ 仅用于 LOCAL_FILE，EXTERNAL_READ 仅用于 HTTPS_URL。LOCATED_ONLY/UNAVAILABLE 允许定位记录，但不能成为数值已核实的证明。

UNVERIFIED 的五个验证字段全部为 null；已知发布日期或文章自述版本写 source_version/notes，不塞入验证字段冒充实验或源码绑定。VERSION_BOUND_VERIFIED 必须满足：来源已读，game_build、method、evidence_locator 非空，且 model_version 或 asset_scope 至少一项非空。该状态说明有版本绑定证据，不能凭字段齐全证明机制正确。

Carto `1.0.17` 是导出器版本，不能直接填作游戏 build；当前输入映射确认也不能证明出行率、乘员率或货运默认。

### 2.2 定位与只读边界

- LOCAL_FILE 的 target 必须为仓库相对路径；拒绝绝对路径、盘符、UNC、反斜杠、空段和 `..`。解析后再次确认处于仓库范围且是文件；指向仓库外的符号链接/重解析路径不能作为可读本地来源。
- 源文件不由目录程序执行或导入。R1 和代码定位按章节/符号记录，行号只是辅助，不作为长期身份。
- HTTPS_URL 必须具有非空主机，不含用户信息；校验仅解析字符串，不请求 URL、访问私有主机或探查网络状态。
- 没有读到的 URL 可以合法登记为 UNAVAILABLE/LOCATED_ONLY，并统计为资料缺口。存在 URL 不代表页面可访问、标题正确或内容已读。

## 3. Parameter：仅表示一个明确定义的量

### 3.1 字段

Parameter 必需字段为 `parameter_id`、`name`、`parameter_domain`、`definition`、`scope`、`quantity`、`value_status`、`value`、`range`、`source_refs`、`assumptions`、`constraints`、`usage_limit`、`rule_refs`、`gaps`、`consumer_tasks`。

| 字段 | 类型与规则 |
|---|---|
| 身份 | parameter_id 按 ID 规则；name/definition 非空；一项只代表一个量、一种分母和一个明确用途 |
| `parameter_domain` | DEMAND、SERVICE、GEOMETRY、REFERENCE、TEST |
| `scope` | 对象：land_use_types、business_subtypes、component、mode_scope、purpose_scope、notes，详见 3.2 |
| `quantity` | 对象：unit_status、unit_id、quantity_basis、time_basis、notes，详见 3.3 |
| `value_status` | UNKNOWN、EVIDENCED_CANDIDATE、THEORETICAL_ASSUMPTION、REFERENCE_ONLY、SYNTHETIC_ONLY |
| `value` | 有限 JSON 数值或 null；布尔不是数值；不支持字符串数值、数组或表达式 |
| `range` | null 或对象 lower/upper，两端均为有限数值且 lower≤upper；仅表示同口径有依据的取值范围，不是通用置信区间 |
| `source_refs` | 非空 SourceRef 数组；所有 source_id 存在，不能只写 URL 或散文代替关联 |
| `assumptions` | 字符串数组；每项非空，允许空数组；THEORETICAL_ASSUMPTION 时必须非空 |
| `constraints` | Constraint 数组，允许为空；见 3.4；不替代 P 运行边界 |
| `usage_limit` | 非空字符串，说明当前用途与限制；不得授权算法使用或改变权限 |
| `rule_refs` | 非空字符串数组，引用 R1/计划等规则位置；不是数值证据 |
| `gaps` | Gap 数组，允许为空；未知字段必须逐项登记 |
| `consumer_tasks` | 非空且无重复的字符串数组；限 P0-03、P0-05、Q-03.1、Q-07.0，新增消费者需设计版本更新 |

RULE_ONLY 不进入 Parameter：白名单、机场去重等无数值规则由 rule_refs 和来源摘要表达。这样不用给规则强行分配单位或 value=0。

### 3.2 适用范围

scope 的 land_use_types、business_subtypes、mode_scope、purpose_scope 均为字符串数组；允许空，但若适用类型、方式或目的未知，必须在 gaps 中指明相应字段。notes 非空，component 为 WHOLE、RESIDENTIAL、COMMERCIAL、NOT_APPLICABLE 或 UNRESOLVED。

land_use_types 仅引用现有枚举值：residential、residential_commercial、commercial、industrial、office、public_service、transport、protection、other。目录不扩展核心枚举。

学校、机场保留为 business_subtypes 的说明性标签，不由 Q 自动映射为公共服务或交通用地默认。混合用地记录使用住宅/商业 component 和明确分母；不把局部覆盖反向推广为纯商业默认。

mode_scope 允许 car_passenger、bus_passenger、metro_passenger、rail_passenger、sea_passenger、road_freight、NOT_APPLICABLE。NOT_APPLICABLE 必须单独出现。步行/骑行、出租车、有轨电车、内部航空及非公路货运不得进入 Parameter 的适用方式；来源正文出现这些方式时在来源 notes 记录背景，不丢弃整份来源。

空数组不表示“全部适用”，目的标签也不是 P 的最终目的枚举。UNRESOLVED component 必须有对应缺口；机场记录引用 D4 去重规则，不保存实际 gateway_id、host_zone_id 或批次账本，实际 OD 归 P。

### 3.3 数量与时间语义

unit_status 为 KNOWN 或 UNRESOLVED。KNOWN 要求 unit_id 在本版词汇内；UNRESOLVED 要求 unit_id=null 且 gaps 含 quantity.unit_id。quantity_basis、notes 为非空字符串，说明分母和统计对象；不同 basis 即使单位同名也不能自动转换。

初始单位词汇按来源和模型查明后使用：person、job、seat、passenger_trip、vehicle_trip、person_per_m2、job_per_m2、passenger_trip_per_person_per_period、passenger_trip_per_job_per_period、passenger_trip_per_period、vehicle_trip_per_period、passenger_trip_per_vehicle_trip、kg_per_period、kg_per_vehicle_trip、game_resource_unit_per_period、game_resource_unit_per_vehicle_trip、s、min、m、inverse_m、ratio、percent、km_per_km2、km。

本版仅检查单位词汇与语义描述，不建立任意单位表达式解析器，不自动转换 km/m、percent/ratio 或 s/min，也不把游戏资源单位换成质量。新单位需版本化扩展；在确认前可以合法保持 UNKNOWN/UNRESOLVED。

time_basis 必需字段为 `status`、`clock`、`period_id`、`duration_seconds`、`notes`：

| status | 其它字段 |
|---|---|
| KNOWN | clock 为 SIMULATION 或 REAL_WORLD；period_id 非空；duration_seconds 为有限正数；notes 非空说明时段意义 |
| UNRESOLVED | clock/period_id/duration_seconds 全部 null，notes 非空；gaps 包含 quantity.time_basis |
| NOT_APPLICABLE | clock/period_id/duration_seconds 全部 null；notes 非空说明为什么无时间分母或时间适用条件 |

以 `_per_period` 结尾的单位不允许 NOT_APPLICABLE。其时间基准未知时，参数只能是 UNKNOWN 或非消费的 REFERENCE_ONLY/SYNTHETIC_ONLY，且缺口明示。平均乘员率等虽然无时间维度，也需通过 notes 说明是否仅适用于特定时段，不能假定全年恒定。

### 3.4 数值状态与边界

Constraint 的必需字段为 kind、source_refs；kind 为 NONNEGATIVE、STRICTLY_POSITIVE、UNIT_INTERVAL 或 PERCENT_INTERVAL；source_refs 为非空 SourceRef 数组，记录这条约束的维度/定义依据，不能只附数值来源。目录数值与 range 两端都受这些边界约束。

单位为 passenger_trip_per_vehicle_trip、kg_per_vehicle_trip、game_resource_unit_per_vehicle_trip 的有数值条目必须显式包含 STRICTLY_POSITIVE，缺该约束本身也拒绝；UNKNOWN 可以先登记此定义约束而不填值。不能删掉约束来放行零乘员率或零有效载荷。混合构成比例只有分母和比例定义已经明确时才登记 UNIT_INTERVAL，不把所有 ratio 都误判为份额；基础底界等有符号高程也不能套用全局非负限制。

| value_status | value/range、来源和缺口要求 |
|---|---|
| UNKNOWN | value=null 且 range=null；gaps 至少包含 value；可以引用规则/定义，不需要伪造 VALUE 来源 |
| EVIDENCED_CANDIDATE | value 非空，range 可空；至少一个 VALUE 引用指向已读且不是 TEST_FIXTURE 的来源；单位 KNOWN，时间 KNOWN/NOT_APPLICABLE，scope 和数量口径无未决缺口；notes 明确证据性质，不声称已批准 |
| THEORETICAL_ASSUMPTION | value 非空，range 可空；至少一个 ASSUMPTION 引用指向已读非测试来源；assumptions 非空；单位、时间与 scope 要求同上；必须描述模型前提，仍未批准 |
| REFERENCE_ONLY | value 非空，range 可空；至少一个 VALUE 引用指向已读非测试来源；parameter_domain=REFERENCE；未知口径可以保留，但必须有缺口，不能用于计算 |
| SYNTHETIC_ONLY | value 非空，range 可空；至少一个 TEST 引用指向已读 TEST_FIXTURE；parameter_domain=TEST；未知口径明确列缺口，仅用于目录测试或契约测试 |

若已有可信范围却没有可选点值，先在来源 notes 记录范围线索并保持 UNKNOWN；本版不创建只有范围即可消费的隐式分支。有数值的状态出现 range 时，需精确的数值/假设来源支持范围，且 value 落在其内；字段齐全不能替代人工判断。

以上所有状态均不自动获得消费或默认批准。纯数值 0 仅能在有证据、口径明确且约束允许时登记为候选或假设；UNKNOWN 不能靠 0 通过校验。

## 4. InventoryGroup：保留未拆清的字段组

必需字段为 group_id、name、definition、source_refs、rule_refs、gaps、consumer_tasks。ID 和关联规则同上；name/definition 非空，source_refs/rule_refs/consumer_tasks 非空，gaps 非空且至少含 INVENTORY_SPLIT。

InventoryGroup 没有 value、range、unit、状态批准字段。它表示资料需求而不是数值参数，不得传入计算。

来源盘点中的 DEM-03、DEM-08、SUP-02、GEO-01、GEO-02 等涵盖多个量，先作为组登记。例如宽度、高度、覆土和基础底界不能共享一个值；库存学位和访问人次不能共用统计单位。单项拆清后可保留组作为追溯记录，组与参数使用不同 ID；后续如需要成员关联，应另明确版本化字段，不能靠相似 ID 自动推断。

## 5. 校验结果、错误语义与版本边界

### 5.1 三类结果

- ERROR：结构或一致性错误，文件拒绝。包括重复 JSON 键、未知字段、错类型、数值非有限、来源悬空、状态矛盾、单位不在词汇、排除方式、越界本地定位等。
- GAP：结构合法且明确登记的资料缺口。UNKNOWN、UNRESOLVED、UNAVAILABLE 和未拆分组允许通过结构检查；缺口计数必须可见，不称默认可用。
- NOTE：已合法记录的参考、合成、候选或假设用途说明。即使数值来源完整，本版仍无 approved/production_ready 字段。

后续 Issue 建议字段：severity、code、record_id、field_path、message；输出文件/字段位置，不倾倒来源正文、绝对私有路径或整份异常堆栈。

建议错误码分组：Q03_SCHEMA、Q03_JSON_DUPLICATE_KEY、Q03_NUMBER、Q03_DUPLICATE_ID、Q03_SOURCE_REF、Q03_SOURCE_STATE、Q03_VALUE_STATE、Q03_UNIT、Q03_TIME、Q03_SCOPE、Q03_PATH、Q03_CONSTRAINT。各码仅用于 Q 校验，不改 P 的 ContractError 或 AdapterError。

### 5.2 读取与退出

默认校验入口提案：`conda run -n csl2-planner --no-capture-output python -s scripts/check_q03_catalog.py`。该脚本目前不存在，命令未运行。

后续默认动作是在仓库定位 Q 目录，执行结构校验和独立期望的轻量正反 fixture，不联网、不要求私有数据或环境变量。目录缺失、读取失败、schema 未知、ERROR 或自检失败均退出非零；合法缺口不冒充失败，也不计作算法通过。

JSON 解析必须拒绝重复对象键、NaN/Infinity/-Infinity；数值检查排除 bool，并对极大整数或转换溢出给可读错误。只有整个目录校验成功后才返回只读记录；不能先消费部分条目，再发现后面存在结构错误。

本地来源文件只核路径边界和存在性，不读其正文或执行。复验不安装依赖、不调整 GIS 环境。默认摘要建议明确报告参数数、未拆分组数、UNKNOWN 数、缺口数、结构 ERROR 数，以及“生产默认批准：无”；不输出 planning_ready=true。

catalog_version、draft_schema_version、来源版本或消费者基线发生变化时，旧校验报告不能继续沿用。当前结构合法性不是来源未变化证明；实际消费绑定与 source manifest/hash、input_revision 等由 P 侧消费协议定义，不由 Q 文档越权实现。

## 6. 后续自包含校验案例设计

以下是待实现的验收设计，不是已执行成绩。每例使用轻量内存 JSON、临时仓库内 fixture 或合成来源；合成数值明确与生产目录分离。

| 案例 | 独立预期 |
|---|---|
| 合法 UNKNOWN 单项，value/range=null，单位/时段未知且逐项列缺口 | 无 ERROR，有 GAP；默认未批准 |
| 合法未拆分组，parameters 为空 | 结构通过，报告组数及零单项，不报目录全部完成 |
| 两数组同时为空或 sources 为空 | Q03_SCHEMA |
| 重复 JSON 键、重复来源 ID、重复参数/组 ID | 拒绝；不能采用最后一个值 |
| 未知结构版本、未知键、注入 editable/approved | Q03_SCHEMA |
| 字符串数值、bool、NaN、Infinity、溢出数值 | Q03_NUMBER；失败非零 |
| UNKNOWN 带 0、数值或 range | Q03_VALUE_STATE |
| 只有 RULE/DEFINITION 引用，却标记有依据数值 | Q03_VALUE_STATE |
| 悬空来源、定位-only/不可访问来源支持已核数值 | Q03_SOURCE_REF 或 Q03_VALUE_STATE |
| LOCAL_READ 配 URL、EXTERNAL_READ 配本地路径、版本验证字段不全 | Q03_SOURCE_STATE |
| 合成值提升为 EVIDENCED_CANDIDATE；测试数值缺 TEST 引用 | Q03_VALUE_STATE |
| 理论假设无前提、reference/test 域与状态不符 | Q03_VALUE_STATE |
| 未知单位未列缺口；每时段单位声明无时间；时段长度≤0 | Q03_UNIT 或 Q03_TIME |
| 单位相同但面积/货物分母不同 | 不自动合并或转换；保留 basis 和 notes |
| 零乘员率/零有效载荷违反 STRICTLY_POSITIVE；反序或越界 range | Q03_CONSTRAINT 或 Q03_VALUE_STATE |
| 步行、出租车、有轨电车、内部航空或非公路货运作为适用方式 | Q03_SCOPE |
| 来源 notes 提到排除方式，Parameter 只适用允许方式 | 合法保留来源背景，不误拒整份来源 |
| 本地绝对路径、..、UNC、仓库外重解析目标、缺文件 | Q03_PATH；不越界读取 |
| 合法 UNKNOWN 机场需求引用 D4 | 资料缺口可见；不生成 gateway、宿主映射或去重计算 |
| 结构通过且存在 EVIDENCED_CANDIDATE | 只报告候选，生产默认批准仍为无 |
